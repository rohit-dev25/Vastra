# Vastra --- E-commerce Web Application

Vastra is a full-stack e-commerce application with a customer
storefront, an admin panel, and an Express/MongoDB backend. The customer
frontend and admin panel can be deployed separately on Vercel, while the
backend runs on Render.

## Project Structure

``` text
Vastra/
├── frontend/   # Customer-facing Vite application
├── admin/      # Admin dashboard (Vite application)
└── backend/    # Express API
```

## Technology Stack

### Frontend and Admin

-   React
-   Vite
-   JavaScript
-   Tailwind CSS / CSS
-   Axios for API requests

### Backend

-   Node.js
-   Express
-   MongoDB with Mongoose
-   JWT-based authentication
-   Multer and Cloudinary for image handling
-   Razorpay payment integration

> Update this list if your repository uses additional libraries or a
> different configuration.

## Features

-   Customer storefront and product browsing
-   User registration and login
-   Cart management, including size selection
-   Order placement and order management
-   Admin panel for managing store data
-   Product image handling
-   Razorpay checkout integration

## Deployment Overview

  Component             Hosting   Root directory
  --------------------- --------- ----------------
  Customer storefront   Vercel    `frontend`
  Admin panel           Vercel    `admin`
  Backend API           Render    `backend`

### 1. Deploy the backend to Render

1.  Create a Render Web Service connected to your GitHub repository.
2.  Set the root directory to `backend`.
3.  Configure the build/start commands to match your backend
    `package.json` (commonly `npm install` and `npm start`).
4.  Add the backend environment variables in Render's Environment
    settings.
5.  Deploy and confirm that the service starts successfully.

Backend URL currently used by the frontend:

``` text
https://vastra-backend-jcls.onrender.com
```

Do not assume this URL is correct forever; replace it if your Render
service URL changes.

### 2. Deploy the customer storefront to Vercel

1.  Import the Vastra GitHub repository into Vercel.
2.  Choose **Import single project** for the `frontend` directory, or
    set the Root Directory to `frontend`.
3.  Set the framework preset to **Vite**.
4.  Add the environment variables below.
5.  Deploy and open the generated Vercel URL.

Required frontend environment variables:

  Variable                 Value
  ------------------------ --------------------------------------------
  `VITE_BACKEND_URL`       `https://vastra-backend-jcls.onrender.com`
  `VITE_RAZORPAY_KEY_ID`   Your Razorpay Key ID

Vite exposes variables prefixed with `VITE_` to browser code. **Never
put private keys or secrets in Vercel frontend environment variables.**
The Razorpay Key Secret must remain on the backend.

### 3. Deploy the admin panel to Vercel

Create a second Vercel project from the same repository:

1.  Choose **Import single project** for the `admin` directory, or set
    the Root Directory to `admin`.
2.  Set the framework preset to **Vite**.
3.  Add this environment variable:

  Variable             Value
  -------------------- --------------------------------------------
  `VITE_BACKEND_URL`   `https://vastra-backend-jcls.onrender.com`

4.  Deploy and open the generated admin URL.

The storefront and admin panel should be separate Vercel projects, each
with its own root directory.

## Backend Configuration and Security

Set the required backend environment variables in Render, based on the
backend's `.env` file and source code. These commonly include:

-   `MONGODB_URI` --- MongoDB connection string
-   `JWT_SECRET` --- secret used to sign authentication tokens
-   `CLOUDINARY_CLOUD_NAME`
-   `CLOUDINARY_API_KEY`
-   `CLOUDINARY_API_SECRET`
-   Razorpay credentials, such as `RAZORPAY_KEY_ID` and
    `RAZORPAY_KEY_SECRET`
-   Any required port or frontend-origin configuration

Use the exact variable names expected by your code. Do not commit `.env`
files or real credentials to GitHub.

### CORS

Configure the backend to allow requests from both deployed Vercel
origins:

-   Customer storefront URL
-   Admin panel URL

Add the actual URLs generated by Vercel to the backend's CORS allowlist.
Update this configuration whenever the deployed domains change.

## Local Development

Run each application in its own terminal.

### Backend

``` bash
cd backend
npm install
npm run dev
```

Use the script defined in `backend/package.json`; if there is no `dev`
script, use the configured start command instead.

### Customer storefront

``` bash
cd frontend
npm install
npm run dev
```

### Admin panel

``` bash
cd admin
npm install
npm run dev
```

Create local environment files using the variable names required by each
app. For local frontend development, the backend URL may point to your
local API server. Never commit those files.

## Production Testing Checklist

After deployment, verify each item:

-   [ ] Storefront opens without a blank screen.
-   [ ] Products load from the Render API.
-   [ ] Product images display correctly.
-   [ ] Registration and login work.
-   [ ] Add-to-cart works after selecting a size.
-   [ ] Cart contents and totals are correct.
-   [ ] Orders can be placed and the order history loads.
-   [ ] Razorpay checkout works in the intended test/live mode.
-   [ ] Admin panel can reach the backend.
-   [ ] Admin actions work as expected.
-   [ ] Browser console and Network tab show no unexpected errors.

If products do not load, open browser DevTools (`F12`) and inspect the
Network tab for the product-list API request. Check the request URL, the
Render service status, environment variable names, and CORS
configuration.

If you change environment variables in Vercel, redeploy the relevant
project so the new values are included in the build.

## Troubleshooting

### API requests fail

-   Confirm `VITE_BACKEND_URL` matches the deployed Render URL.
-   Check that the frontend code reads
    `import.meta.env.VITE_BACKEND_URL`.
-   Check the browser Network tab and Render logs.

### CORS errors

-   Add the exact Vercel storefront and admin origins to the backend
    CORS configuration.
-   Ensure the backend responds to preflight `OPTIONS` requests if
    required.

### Vercel build fails

-   Check the build log for missing dependencies, TypeScript/lint
    errors, or incorrect build scripts.
-   Confirm the Root Directory is `frontend` or `admin` for the
    corresponding project.
-   Confirm the output directory is `dist` for a standard Vite build.

### Razorpay checkout fails

-   Confirm the frontend uses the Razorpay Key ID.
-   Keep the Key Secret on the backend only.
-   Verify that the backend creates and verifies payments correctly and
    that test/live credentials match.

## Security Notes

-   Never commit `.env` files, passwords, JWT secrets, database
    credentials, Cloudinary secrets, or Razorpay Key Secrets.
-   Treat all `VITE_*` values as public because they are bundled into
    client-side code.
-   Use HTTPS in production.
-   Validate and authorize admin-only API endpoints on the backend;
    hiding admin UI controls is not sufficient.
-   If any secret has been exposed, rotate it with the relevant
    provider.
